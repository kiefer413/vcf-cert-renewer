# VCF Certificate Renewer v1.3.1

A focused deployment and documentation patch on v1.3.0. The application behavior,
VCF/NSX authentication, dependencies and four-target FULL_RENEW scope are unchanged.

- Official suspended-by-default Kubernetes CronJob, ConfigMap example, namespace
  and persistent ACME-state claim, using the same multi-architecture GHCR image.
- Non-root, read-only runtime with mounted file secrets, no API token or RBAC.
- Plan-first setup, safe secret creation, daily scheduling, troubleshooting,
  upgrades and non-destructive cleanup in the standalone container guide.
- Offline checks for manifest configuration and equivalent mounted-secret runtime.
- PVC remains the recommended default: `/data/acme` preserves lego's ACME account
  private key, registration and identity, especially for custom ACME CAs/EAB.
  CSR/fullchain artifacts can be regenerated. Writable `emptyDir` is technically
  possible when the CA permits repeated registration, but Pod recreation may
  trigger a new registration that fails due to registration limits, EAB or custom
  CA rules. CronJob renewal output goes to stdout/container logs (`kubectl logs`),
  not reports under `/data`.

See [CONTAINER_DEPLOYMENT.md](../../CONTAINER_DEPLOYMENT.md).
The v1.3.1 image is available only after an explicitly authorized release push
and successful release workflow. Until then, use the published v1.3.0 image.
