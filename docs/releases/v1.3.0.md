# VCF Certificate Renewer v1.3.0

v1.3.0 adds portable mounted-file credentials and a non-root batch container.
Existing direct environment configuration, generic ACME v2, optional EAB and
legacy ACME_MODE behavior remain supported.

- Central NAME_FILE support for API tokens, passwords, legacy client secrets,
  DNS TSIG and EAB credentials, including the existing credential identifiers.
- Strict direct/file conflict errors, newline-only trimming, safe diagnostics and
  no secret values in configuration-object representations.
- systemd Credentials drop-in and protected-file, Docker, Podman and Compose examples.
- Python 3.12.12 / Debian bookworm slim and lego 5.4.1; linux/amd64 and linux/arm64.
- Tag-gated GHCR workflow with offline validation before publishing stable aliases.

The image is a batch job. Persist /data to retain ACME accounts and renewal
artifacts. `_FILE` does not encrypt backing files; protect them through your
secret store. Lego still receives its required TSIG/EAB credentials in its own
child environment, never in command-line arguments.

No changes to VCF/NSX authentication flows or mutation scope: Operations, SDDC
Manager, vCenter and NSX Manager VIP remain the only FULL_RENEW targets.
All other targets retain their existing read-only/unsupported behavior.

See [deployment and migration](../secret-handling.md). Before migrating, remove
corresponding direct values from all configuration layers, then set NAME_FILE.
